## Teaching after attempt and focused check — November12

Tutor explains: for https://reports.example.com/billing, hostname is reports.example.com and path is /billing. The certificate's server identity check uses the hostname. The stipulated successful handshake means that check already passed in this case. The application then receives the HTTP request and returns401/login_required because the required session cookie/token is absent. Changing the certificate does not supply application login credentials. No claim about every possible401 or about mutual TLS is made; scenario explicitly excludes redirects/mTLS.

Focused guided follow-up: "If the URL changes to https://reports.example.com/exports on the same server, does that require a different certificate? Why?" Same certificate remains trusted/unexpired and covers reports.example.com, no redirect/new host or other configuration changes. This checks the stated hostname/path distinction after direct teaching; any correct answer is guided evidence, not independent delayed retention. Correct follow-up recorded below; no additional review occurrence for this check.
